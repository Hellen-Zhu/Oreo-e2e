SIT 造数：一条命令为 UAT 准备整套真实交易

UAT 每一轮都需要 SIT 上有覆盖所有产品、所有生命周期事件的交易，按指定的 portfolio 和 entity 下单，还要有 Cortex 导出的 dat 文件。这套工具把造单、审批、记录、出报告和导出 dat 串成一条流水线，放在 oreo-e2e 项目里，和 E2E 用例共用同一套请求。

00

开场：UAT 要什么数据

1 分钟

UAT 开始前，业务要在 SIT 上看到一批“像真的一样”的交易：每个产品至少一笔 live 交易，每种生命周期事件（Allocation、Amendment、Termination、Novation、Step-out……）各做过一次，而且要落在业务指定的 portfolio 和 entity 下，再配上从 Cortex 导出的 dat 文件。

手工做这件事，要在页面上一笔一笔录入、找人审批、把 trade ID 抄下来，再到 Cortex 里一笔一笔导出。量大、容易错，SIT 一刷新又得重来，而且很难说清这一轮到底造了哪些单、哪几笔失败了。

今天演示的，就是把这整件事变成可重复、可追溯、失败可补跑的一条命令。

01

一页看全流程

2 分钟
造单 · 在 SIT 上
造数清单Excel → feature 的一行行种子用例 + catalog
→
SeedTest走 API 下单，checker 自动审批；新交易和事件两组并行
→
Manifest每笔结果一行：trade ID、任务、portfolio、错误
→
seed-reportHTML + CSV，直接发给 UAT
dat 文件 · 在 Cortex 上
seed-dats每个用例该用哪个 dat、还缺哪些
→
Cortex 导出脚本给一批 trade ID，自动点完导出流程
→
dat 文件放回用例对应的路径，下一轮下单就用它

上面一路在 SIT 上造单：清单里每一行是一个种子用例，SeedTest 读清单，通过和 E2E 测试同一个 API 客户端下单、审批，把每一笔的结果写进 manifest，最后生成一份给 UAT 的报告。

下面一路解决 dat 文件：先列出每个用例需要哪个 dat、哪些还没有，再用脚本到 Cortex 里按 trade ID 批量导出。

关键的设计是复用：造数和 E2E 用例用同一套请求体、同一套事件数据、同一个 API 客户端。API 改了，修一处，两边都好。

02

种子用例：一行一笔单

2 分钟
屏幕打开 src/test/resources/seed/features/seed_new_trades.feature，再打开 seed/catalog.json 里对应的 cases。
| case           | composition    | product_id | taxonomy      |
| SEED-TRADE-024 | FX_PSCRIPT_TRF | FX_PSCRIPT | ComplexExotic |
"SEED-TRADE-024": { "request": { "basic": {
    "portfolioId":   "EXAMPLE_PORTFOLIO_E",
    "riskPortfolio": "EXAMPLE_PORTFOLIO_E",
    "scbEntity":     "EXAMPLE_ENTITY_B" } } }

Excel 清单的每一行，在这里就是 feature 里的一行，有一个固定的用例编号，比如 SEED-TRADE-024。UAT 认的就是这个编号，所以编号只往后加，不重排。

这一行要用什么 portfolio、什么 entity、哪个 dat 文件，写在 catalog 里同名的条目下。没写的部分，就用和 E2E 一样的默认请求体。

仓库里放的都是占位符，EXAMPLE_PORTFOLIO_* 这样的值；真实的 SIT 值只在公司副本里，不进 git。

类型编号数量每笔做什么
新交易SEED-TRADE-001…03838按产品下一笔 live 交易
生命周期事件SEED-EVENT-001…02020先下一笔新交易，再在上面做事件
Step-inSEED-STEPIN-001…0022用 Step-in 的请求体下一笔交易
03

生命周期事件与 Step-in

2 分钟
屏幕打开 seed/features/seed_lifecycle_events.feature，指一下 case、event、composition 三列。

事件用例覆盖 10 类事件，在 FX_TRF 和 FX_PSCRIPT_TRF 两个产品上各做一遍，一共 20 个。每个用例都会先下一笔新的 live 交易，再在这笔交易上发事件；事件产生审批任务的，由 checker 自动审批，生成的子交易（比如 Allocation 拆出来的两笔）也一起记下来。

事件的请求直接复用 E2E 正向用例的数据，不再维护第二份。比如 Allocation 在 E2E 里写的是“按名义本金 50% / 50% 拆分”，造数时会先读这笔交易的实际名义本金，换算成金额再发，和 E2E 的做法完全一致。

每个事件用例在 catalog 里都点名自己的 dat 文件，用自己的 portfolio 和 entity；Step-in full / partial 也一样，放在事件这一组里一起跑、一起出报告。

事件发送方式
allocation-full · withdrawal · termination · partial-termination · portfolio-reassignmenttrigger-event
remaining-party-full / partial · step-out-full / partialtrigger-event
amendment交易的 update 接口
stepin-full · stepin-partial用 Step-in 请求体直接下单
留意一个事件用例如果没写 dat 文件名，工具会直接报错停下，而不是悄悄用 E2E 的 dat 文件下单。这是踩过一次坑之后加的保护。
04

失败只重跑失败的

1 分钟
屏幕在终端演示两条命令（公司机器上）。
# 全量跑一次
mvn -B test -Dtest=SeedTest

# 只补跑失败的两个用例
mvn -B test -Dtest=SeedTest "-Dcucumber.options=--name ^\[(SEED-TRADE-001|SEED-EVENT-004)\].*$"

# 把第一次全量和之后的补跑合成一份报告
mvn -Ptest-data process-test-classes "-Dexec.args=seed-report 20261120-153000.."

SIT 不稳定的时候，难免有几笔失败。以前只能整批重来，重复下单；现在按用例编号只补跑失败的。

每次运行都会单独留一份记录。出报告时可以把“第一次全量 + 之后的补跑”合并起来，同一个用例以最新一次的结果为准：第一次失败、补跑成功的，报告里就显示成功和新的 trade ID。

06

Cortex dat 自动导出

2 分钟
屏幕在装有 Cortex 的 Windows 机器上，打开 TDS Browser，运行脚本，让大家看它自己点完流程。
TDS Browser 输入 trade ID，F9 加载→ 打开交易，Export › View→ 只显示 INSTRUMENT 列，打开 ITradeable→ Export › Save As，存成 <trade ID>.dat 
python scripts/cortex_dat_export.py --file trades.txt

dat 文件以前要在 Cortex 里一笔一笔点出来。现在给脚本一个 trade ID 列表，它会自己完成整套点击流程，逐笔保存成 dat 文件。

脚本会先关掉上一次留下的窗口，等窗口稳定了再操作；已经导出过的会跳过，一笔失败不影响后面的，每笔结果写进一份日志。导出的文件放在项目外面，因为里面是真实数据。

07

数据安全与质量

1 分钟

真实数据不进代码库。portfolio、entity、trade ID、dat 文件，在仓库里都是占位符；真实值只在公司副本或本地被 git 忽略的文件里。

错了就早点停。清单里还写着 TODO 的值、没点名 dat 文件的事件用例、编号重复、找不到的产品，都会在下单前就报错，而不是造出一笔错误的单。

离线就能检查。清单、catalog、报告和 dat 规则一共有 184 项离线检查，不连 SIT 就能跑，改动之后先过这一关。

Q&A

为什么放在 E2E 项目里？—— 因为请求、数据、API 客户端都和 E2E 用例共用，API 一变两边一起修，不会出现两套数据慢慢对不上的问题。

报告里的 payload 会不会泄露真实数据？—— 报告和 manifest 只生成在公司机器的 target 目录，从不提交；对外发送前要注意里面有真实的 portfolio 和 entity。

数据过期了怎么办？—— 交易的日期是相对下单当天算的（T+N），SIT 上别人也会改动这些交易，所以造好的数据会慢慢过期。办法是重新跑一遍：每个 sprint 或每次 SIT 刷新后整套重建，新的一轮按当天时间下单；也可以按标签或用例编号只重建一部分。每一轮的报告和对应的版本一起留存，过期的旧单不用去修。

会不会重复造单？—— 补跑只跑指定的用例；报告合并时同一用例只保留最新结果。
