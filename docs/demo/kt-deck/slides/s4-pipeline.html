第 2 天 · AI 工作流

两条流水线，每一步都有人审批

/writebddfeatures · bdd-agent

story → feature 文件

1. 拆成测试点，决定放 API 还是 UI（qa-layer-test-design）
2. 审批
3. 写成业务语言的 Gherkin（qa-bdd-feature-authoring）
4. 审批

/codetestcases · test-agent

feature → 能跑的 case

1. 补齐数据、snippet、glue（qa-api-test-authoring、qa-e2e-test-authoring）
2. 离线检查和 dry run（qa-bdd-test-execution）
3. 审批后用最窄的 filter 真实运行

跑出来的产品缺陷用 qa-defect-reporting 起草 ADO Bug，确认之后才创建。

这一段配合 docs/demo/oreo-ai-workflow.html，里面有交接物、失败分流和一个完整的例子。强调 AI 生成的内容同样要经过人审批和 code review。
